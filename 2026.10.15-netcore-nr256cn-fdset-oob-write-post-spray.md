# Out-of-Bounds Write in Scheduler fd_set Handling under Concurrent POST Uploads

- Published: 2026-10-16
- Supplier: Netcore
- Product: NR256CN
- Affected version: NR256CN-V1.5.140116.bin
- Vulnerability type: Out-of-Bounds Write (CWE-787)
- Contributors: Zhou Ao, Yin Luxing, Lu Fangzhou, Liu Xin @Nebusec

## Affected Component / Code Path
- `loop.c`
- `read_config_files.c`
- `process_header_end.c`
- `block_request.c`
- `free_request.c`

## Disclosure Note
This public reference is intentionally limited to identification details required for CVE coordination.
Proof-of-concept material, reproduction steps, and additional technical detail are withheld at this stage.

## Summary
The request scheduler zeroes only 32 dwords of its fd_set arrays, so it can represent at most 1024 descriptors, while the connection cap ignores the extra body descriptor allocated for every POST request before its body is drained. Scheduler bookkeeping indexes the arrays at fd >> 5 without bounds checks, so holding many concurrent POST uploads open writes request bits outside the fixed arrays.

## Impact
An unauthenticated remote attacker can corrupt scheduler state and crash the web management service by holding concurrent uploads open.
